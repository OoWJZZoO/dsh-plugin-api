## 2. 单面与非门面义务汇总

- **只有 host 无 client 半面**：`workflows.*`、`sessions.compaction.*`、`services.*`（含 `appExit`）、coordination/checkpoint 面（各线 §10 六问判定为 host-only）。缺口已按 Req 1.4 在该行标注（上表「host/client」列）。
- **非门面义务（Req 1.6，不计入覆盖分母）**：各项目的 UI 渲染、皮肤、面板、业务算法、通知呈现、记忆算法、用量展示文案，以及 **home 路径解析本身**（见 §2.1）。已逐行标注，未被静默丢弃。
- **诚实降级（Req 13.2，不视为缺陷）**：可选包未安装、carrier 缺失、断线、版本错配、合法冲突、用户拒绝、外部 provider 故障——以上表「故障证据」列的 typed 结果为准。
- **能力缺口（Req 9.4 登记）**：`sessions.interactions` 的 question 侧（无 pending/answer seam）与 per-session grant（无可达授权 seam）——两缺口在 `reconciliation.md` §7 与 feature-list §7 登记，**不视为非门面义务**。

### 2.1 home / 数据 scope 映射（Task 3.3，design §5.3）

原样本自带的 home 解析（`DSH_HOME` 环境覆盖 + `~/.dsh` 回退）是**本地计算**，本身不是 DSH API 行为 ⇒ 标为**非门面义务**，不计入覆盖分母；但由它承载的插件数据必须落到声明式 scope 上，映射如下：

| 原形态（样本） | 原数据 scope / 生命周期 | 新承载（受支持路径） | 落地要求 |
|---|---|---|---|
| 消费者自选 home 路径下的自有账本/缓存（cost-meter 账本、memories 数据） | 进程级文件；进程重启后仍在，卸载后是否保留由消费者自定 | `pluginApi.storage`（**profile 档**） | handle 关闭不删数据、`purge` 显式；不在门面外自建第二套共享状态 |
| 直接读 `~/.dsh` 下的官方受管文件（凭据、设置） | 官方受管数据 | 共享 authority：`services.credentials.resolve`（只读）/ `services.settings`（读写） | **禁止**硬编码路径直读官方文件；读取失败按 typed 结果呈现 |
| session 级数据（会话内记录） | 单个 session | session 档（官方 session durable 面：`sessions.durable` / session store） | 每记录只属 session / workspace / profile 三档之一（`docs/standards/durable-state-and-scope.md`） |
| workspace 级数据（事务、快照） | 单个 workspace | workspace 档（`workspaces.transactions` 受管面） | 同上；私有 storage 不旁路共享事务 authority |
| home 路径解析本身 | 本地纯函数，无 DSH 交互 | —（非门面义务） | 不新增 home-path 查询公共成员（design §5.3「不做」） |
